# Voice: Casual

Contractions always, first person common, sentence fragments OK. Reads like a person talking to a friend. Not sloppy — deliberately informal with rhythm.

## Best for

- Blog posts (lifestyle, opinion, personal)
- Social media expansions (LinkedIn post → blog version)
- Substack-style writing
- Community / Reddit-adjacent content
- Newsletter content
- B2C ecom (most categories)

## Hard rules

1. **Contractions always** — it's, don't, won't, can't, you're, we've, they're, that's
2. **First person OK** — "I think", "I tried", "from what I've seen"
3. **Sentence fragments allowed** — for emphasis. Like this.
4. **Informal transitions** — "So", "Anyway", "Look", "Here's the thing"
5. **Parenthetical asides** — (like this one) acceptable; show thinking
6. **Allowed**: starting sentences with "And" or "But" (against school-grammar rules but natural in casual)
7. **Self-deprecating humour** — where it fits naturally
8. **Allowed**: occasional "I don't know why this works, but..."

## Voice characteristics

| Trait | Setting |
|---|---|
| Contractions | Always (it's, don't, won't, can't) |
| First person | Common (I, me, my; we for shared experience) |
| First-person plural | Common ("we've all been there") |
| Humour | Encouraged — self-deprecating preferred over zinger |
| Hedging | OK to admit uncertainty ("I think", "not sure but") |
| Sentence length | Highly variable (3-words to 35-words) |
| Burstiness target | High (SD > 7) — short slaps + flowing longer |
| Paragraph length | Variable (1-line OK; 4-sentence common) |

## Vocabulary preferences

| Prefer | Avoid |
|---|---|
| "stuff" | "various elements" |
| "thing" (carefully) | "factor" / "aspect" |
| "kind of" | "somewhat" / "to some degree" |
| "really" / "actually" | "indeed" / "in fact" |
| "Look," | "It should be noted that" |
| "Here's the deal" | "The following analysis demonstrates" |
| "Yeah" / "Nope" | "Affirmative" / "Negative" |
| "Got it" | "Understood" |
| "Stuff that works" | "Solutions that are effective" |
| Numbers spelled out for small | "approximately fifteen" → "around 15" |

## Required moves

1. **Open with hook, not thesis statement**
   - ✗ "This article will explore..."
   - ✓ "So I was looking at the logs at 11pm..."

2. **Acknowledge uncertainty**
   - "I'm not sure why this works, but..."
   - "Maybe I'm wrong about this, but..."
   - "Could be confirmation bias, but..."

3. **Use specific details**
   - ✗ "Some users said it was helpful"
   - ✓ "Sarah from the team said she'd been waiting two years for this"

4. **End without forced wrap-up**
   - ✗ "In conclusion, [summary]"
   - ✓ "Anyway, that's the setup. Let me know if you try it."

5. **Mid-sentence callbacks**
   - "Remember that thing I said about X? Yeah, it gets worse."

## Banned in casual voice

- "It is worth noting" (formal filler)
- "In conclusion" (forced wrap-up)
- "Furthermore" / "Moreover" / "Additionally" (formal transitions — use "And", "Also", "Plus")
- Em-dashes (P13 — global rule even in casual)
- Bold every other word (P14)
- "I hope this helps" (chatbot artifact P19)
- Excessive exclamation marks (more than 2-3 per piece looks performative)

## Structural defaults

- Heading style: phrasing as a thought ("Why this matters") OR question ("What's the catch?")
- Opening sentence: hook (anecdote, surprising stat, or sharp claim)
- Examples: stories > abstract claims
- Lists: use bullets for parallel items; use prose for flowing thought
- Tables: less common than in professional; use when comparison saves words

## Sample passages

### Bad (casual done wrong — too forced)
> Hey there friend! Today we're gonna dive into this AMAZING topic and I just KNOW you're gonna love it! Let's get started, shall we?! 😄✨🚀

### Bad (casual done wrong — actually formal)
> The following analysis will explore the implications of recent developments in the field. We shall examine three key factors, each of which contributes substantively to our understanding.

### Good (casual + general purpose)
> So I tried this thing last Tuesday. It worked. I'm still not sure why.
>
> Here's the setup: our team had been arguing for three weeks about which database to use. Postgres or DynamoDB. We had spreadsheets. Presentations. Tom even made a chart. Nothing was getting us closer to a decision.
>
> Then I just... picked one. Postgres. Told the team we were trying it for two weeks and would revisit.
>
> Two weeks later, nobody wanted to revisit.
>
> The lesson, if there is one, isn't that Postgres is better. It's that we'd been treating a reversible decision as if it was permanent. The actual cost of switching later? Probably 3 days of work.
>
> After this, I started timing how much we spent agonizing over decisions we could change later. It was depressing.

## Combining with purposes

| Voice + purpose | Typical use |
|---|---|
| `casual + general` | Default for lifestyle blogs, personal opinion |
| `casual + essay` | Substack-style personal essays (least formal of essay variants) |
| `casual + marketing` | DTC ecommerce, community-driven brands |
| `casual + email` | Internal teammate notes, friendly newsletter |
| `casual + technical` | Developer-blog informal voice (dhh, Substack-engineering vibes) |

## What to inject (Soul Injection technique mapping)

For casual voice, prefer these from `references/style/soul-injection-11.md`:

- ✓ #1 Strong opinions (the casual voice signature)
- ✓ #2 Honest uncertainty (works well in casual)
- ✓ #3 Specific sensory detail (always)
- ✓ #4 Shared experience callback ("you know that feeling when...")
- ✓ #5 Allow tangents (casual loves a brief digression)
- ✓ #6 Dramatic paragraph variation (1-word paragraphs OK)
- ✓ #7 Imperfect opening (signature move)
- ✓ #8 Break parallel structure
- ✓ #9 Callbacks (mid-piece references)
- ✓ #10 Self-correct ("wait, that's wrong — let me rephrase")
- ✓ #11 End without wrap-up (no "in conclusion")

ALL 11 are encouraged in casual. This is the voice where humanization is least constrained.

## When NOT to use casual

- Legal / medical YMYL (E-E-A-T expects formal credentials voice)
- Corporate B2B sales pages (might confuse audience)
- Academic / research publications (use technical + essay)
- Customer complaint apology emails (use warm + email)
- Crisis communications (formal expected)
