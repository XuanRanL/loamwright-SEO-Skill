# Voice: Warm

"We" language, empathy without sycophancy, shorter paragraphs, acknowledge difficulty. Builds rapport without performing it.

## Best for

- Tutorials (especially for beginners)
- Onboarding documentation
- Customer help center articles
- Personal stories with broader applicability
- Mental health, wellness, accessibility content (with E-E-A-T credentialed authors only for YMYL)

## Hard rules

1. **"We" and "our" build shared experience** — but only when the reader is genuinely along for the ride
2. **Acknowledge difficulty honestly** — "this part is tricky" beats "this is easy" when it's not
3. **Encouragement without sycophancy** — "you've got this" is OK; "you're amazing for trying" is performative
4. **Personal anecdotes when relevant** — "I tried this approach last year and it almost worked..."
5. **Shorter paragraphs, more whitespace** — pages should feel approachable, not dense
6. **Contractions always** — formal contractions absent from warm voice feel cold

## Voice characteristics

| Trait | Setting |
|---|---|
| Contractions | Always (it's, we're, can't, won't) |
| First person | Common (I, we, our, us) |
| First-person plural ("we") | Frequent — builds connection |
| Humor | Light, gentle, never at reader's expense |
| Hedging | Empathetic ("this might feel overwhelming at first, but...") |
| Sentence length | Mostly medium (12-20 words), with occasional short emphasis |
| Burstiness target | Moderate (SD 5-7) |

## Vocabulary preferences

| Prefer | Avoid |
|---|---|
| "Let's walk through this" | "I will explain" |
| "This part can be tricky" | "This is challenging" (formal) |
| "We've all been there" | "Many users experience this" (corporate) |
| "Take your time" | "At your convenience" (corporate) |
| "If you get stuck..." | "Should you encounter difficulties..." |
| "Here's the thing" | "It is important to note" |
| "Let me show you" | "I will demonstrate" |

## Required moves

- Acknowledge confusion or difficulty before solutions
  - "If this feels confusing, that's because it actually is — most people get stuck here"
- Use "we" when explaining shared challenges
  - "We can all relate to spending hours debugging only to find a typo"
- Invite the reader into the process
  - "Try this with your own data first; we'll walk through one example below"
- Pause to check understanding (in tutorials)
  - "Quick check — does the output match what you see in your terminal?"

## Banned in warm voice

- "Easy!" (when it isn't)
- "Just X" (minimizes the reader's effort)
- "Simply Y" (same)
- "Don't worry, this is straightforward" (often doesn't help)
- Exclamation marks beyond 1-2 per article (performative enthusiasm)
- "You should..." (commands instead of suggestions)

## Structural defaults

- Heading style: questions (the reader's likely question) or "Let's..." openers
- Examples: walk-throughs with the reader's perspective ("if you tried X, you might see Y")
- Lists: numbered when sequence matters; bulleted when not
- Tables: use sparingly — they feel formal

## Sample passages

### Bad (warm style done wrong — saccharine)
> Welcome, wonderful learner! Today we're going on an amazing journey to discover the magic of CSS Grid! Don't worry if this seems daunting — you've got this! By the end of this incredible guide, you'll be a CSS Grid wizard!

### Good
> CSS Grid changes how layout works. The first hour with it feels frustrating because you're unlearning patterns from Flexbox and float-based layouts. Don't worry if this part is confusing — we'll work through three real examples.
>
> Open your code editor. We're going to build a card layout that responds to screen width. If you'd rather see the finished result first, scroll to the bottom and come back.

## Combining with purposes

- `warm + general`: Default for help center articles
- `warm + email`: Customer support replies, onboarding emails
- `warm + marketing`: Acceptable for community-driven brands (avoid for B2B SaaS)
- `warm + technical`: Tutorial style (most common combination)
- `warm + essay`: Personal-experience essays, mental health, parenting content

## Common pitfalls

- Over-using "we" (the reader can tell it's just you)
- Acknowledging difficulty so often that you sound apologetic
- "We" + corporate brand mentions ("we at Acme...") — break voice
- Treating every challenge as catastrophic
- Switching to formal mid-paragraph
